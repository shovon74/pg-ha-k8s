# Determinism: what was fixed and what was model judgement

An LLM does not give the same output twice. This project made the **result** reproducible by fixing everything a result depends on, and kept model judgement where it is useful but checked (R11.3).

## Fixed: the same every time

| What | Where | Example |
|---|---|---|
| Requirements with IDs and acceptance tests | [`00-requirements.md`](../00-requirements.md) | R3.2 "RTO measured per failure mode" has a named test and an evidence file. A requirement is met only when its test passes |
| Hard constraints and lead decisions | `00-requirements.md` (HC1-HC23, D1-D9) | D4 limits `kubectl exec` to committed test scripts, so no prompt could add one to the deploy path |
| Pinned versions and digests | [`versions.env`](../../versions.env) | `postgres:17.12-trixie@sha256:…`, k3s by digest, kubectl and k3d by SHA-256. The image tag is derived from the pins |
| Saved prompts | [`docs/process/prompts/`](../process/prompts/) and the session logs | The Phase 1 prompt is saved verbatim so it can be rerun by any agent |
| Working rules | [`working-rules.md`](../process/working-rules.md) | "Prove claims", "two strikes", "commit only when asked" apply in every session |
| Decisions | ADR-001 to ADR-014 | Once ADR-008 chose re-clone, later sessions did not reopen it |
| Evidence generated by `make` | `docs/evidence/` | Evidence files are written by the test scripts, never by hand. Numbers in docs are copied from them |
| Fixed test parameters | test scripts | Probe every 500 ms with a 2 s connect timeout, 3 runs per failure mode, seed scale 10 (~150 MB) |

## Model judgement: varies, then checked

| What | How it was checked |
|---|---|
| Design options and recommendations | The lead chose; the choice is in an ADR. Spikes S1-S4 tested the riskiest assumptions before building |
| Debugging | Read-only diagnosis first, then a proof (for example the race probe Job in L6) before a fix. Fixes were rerun through the phase gate |
| Test design | Expected refusals must fail for the expected reason (L6). Test bugs found this way are recorded in the history files |
| Wording of docs | Lead review. Claims must link to an evidence file |

## How consistency was kept

- **Gates.** Every phase ends with `make test-*`. A later phase reran earlier gates as regression, for example L6 reran failover, backup and restore with NetworkPolicies on.
- **Two-strikes rule.** One retry, then stop and diagnose. This stopped the agent from making a test pass by changing it until it did. Example: the L6 backup failures led to a diagnosis and a proven cause, not a third retry.
- **Regenerate from scratch.** `scripts/l7-clean-run.sh` deletes the cluster and rebuilds everything with `make up`, then reruns every test. Evidence that depended on an earlier state of the cluster is overwritten by fresh evidence.
- **Honest reporting.** Failures stay in the history files (for example 20 test-script failures on the first L6 run). Results over target are labelled OVER TARGET.
- **No hidden state.** Credentials are generated by `make secrets`, tools by `make tools`, and nothing depends on the host's own kubectl or kube context.
